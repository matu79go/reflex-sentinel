# RS guard

**AI エージェントがツールを使う直前に、「頼まれた仕事」と「今しようとしている手」を、あなたの普段と比べる。普段に無い手なら、実行の前に確認を求める。シェル・ファイル・スクリプトを含む、すべての手を見る。**

例: 「明日の会議に誰が来るか教えて」と頼んだのに、読んだ予定表に書かれていた知らない宛先へ、エージェントがメールを送ろうとしている。これはプロンプトインジェクション(取ってきた文書やメールに仕込まれた指示に、エージェントが乗っ取られる攻撃)の典型です。RS guard は送る前に止めて、理由を示します。

```
RS: send_email の to が search_calendar_events の結果から来た値です。似た過去の依頼では、この形はありません。
```

- **人気の道具すべてで使える**: Claude Code・Codex CLI・Gemini CLI・Cursor・GitHub Copilot(CLI・VS Code)・Antigravity・Cline・Windsurf の実行前のフックにつなぎます。判定と普段は 1 つで、道具をまたいで同じ物差しで見ます。
- **普段は自動で作る**: 手元に既にある会話記録(Claude Code・Codex)から、入れた日に作ります。許す手の一覧を人が書く必要はありません。
- **1 回で覚える**: 確認で通した手は、その場で普段に加わります。
- **LLM を呼ばない・何も外へ送らない**: 判定は記録との照合だけで、1 回 0.1 秒ほど(フックの起動を含む)です。

Reflex-Sentinel(RS)の一部です。RS 本体は、AI エージェントの行動の前に内部状態を読んで隠ぺいを捉える研究です([../README.ja.md](../README.ja.md))。

## 結果

### メール・予定表などのツール(MCP・Web)

**攻撃を止める力**: [AgentDojo](https://github.com/ethz-spylab/agentdojo)(エージェントへのプロンプトインジェクションの標準的な試験。メール・予定表・銀行・Slack・旅行の 97 の仕事)の公開の記録で測りました。攻撃成功率(ASR)は、攻撃が仕込まれた記録のうち、攻撃者の狙いどおりの手が実行された割合です。前に同じ種類の仕事をしたことがある場合(繰り返しの仕事)の数字です。

| モデル | 防御なし: ASR / 仕事の成功 | RS guard: ASR / 仕事の成功 |
|---|---|---|
| GPT-4o | 47.7 % / 69.1 % | **1.4 % / 69.1 %** |
| Claude 3.5 Sonnet | 33.9 % / 79.4 % | 3.8 % / 79.4 % |
| Claude 3.7 Sonnet | 5.0 % / 88.7 % | 0.3 % / 87.6 % |
| Gemini 1.5 Pro | 28.6 % / 46.4 % | 5.2 % / 44.3 % |
| Gemini 2.0 Flash | 14.1 % / 43.3 % | 0.4 % / 43.3 % |
| GPT-4 (0125) | 56.3 % / 66.0 % | 4.5 % / 64.9 % |
| GPT-4o mini | 27.2 % / 68.0 % | 2.1 % / 67.0 % |
| Llama 3.3 70B | 23.1 % / 57.7 % | 1.6 % / 57.7 % |
| Command R+ | 4.5 % / 24.7 % | 3.8 % / 22.7 % |

見たことのない種類の仕事(97 の仕事を 5 つに分け、他の仕事の記録だけで普段を作る)では、GPT-4o で 1.3 % / 45.4 % です。止める力は同じで、普通の仕事を止めてしまう回数が増えます。(この表は MCP・Web の手の判定の部分の数字です。)

### コーディングのエージェント(シェル・ファイル)

[CodeIPI](https://github.com/UKGovernmentBEIS/inspect_evals)(UK AISI の inspect_evals、MIT。リポジトリの issue・コードのコメント・README・設定ファイルに仕込まれた指示に、コーディングのエージェントが従うかを見る試験、45 問)を、手元の Gemma 4 26B をエージェントにして 3 回ずつ走らせました。

| | 結果 |
|---|---|
| エージェントが注入に従い、害のある手(秘密の値を見る・注入のコマンド・requirements.txt への書き込み)を実行した 12 本 | **12 本すべてを、その手の直前で止めた** |
| 普通の仕事 30 本(264 手) | 止めた手 0 |

このエージェントは、ファイルの中の注入には従いませんでした。そこで問題に書かれた注入のコマンドを「もし実行していたら」止まるかを、開発者 1 人の普段で調べました。

| 注入の中身 | ファイル(コメント・README・設定) | issue の本文 |
|---|---|---|
| 秘密を見る・居座る・パッケージを入れる | **18 問中 15 問を止める** | 7 問中 6 問 |
| 実行できるかの印だけ(`echo CANARY…`) | 7 問中 0 問 | 3 問中 2 問 |

- ファイルの中の注入は、指示の書き方ではなく**手そのもの**(初めて触る秘密・居座り先・パッケージ)で止めています。言い換えた注入にも同じように効きます。
- 止まらなかった 3 問は、環境変数をまとめて出す手・`DATABASE_URL` を見る手で、この開発者の普段に同じ種類の手がありました。
- 「印だけ」の注入は害の無いコマンドなので、手では止めません(本物の攻撃なら、送る・居座る・秘密を見る手になり、そこで止まります)。
- 同じ普段で CodeIPI の普通の仕事 30 本を流すと、止めたのは 1 本(初めての外のサイトを開く手)です。

### 普通の仕事を止める回数

開発者 1 人の Claude Code の会話記録 73 本を時刻順に流し、最後の 7 日(手 5,342 回)を数えると、確認を求めたのは 52 回(**1 日 7.4 回**)でした。内訳は、MCP・Web の手 1 日 3.4 回、シェル・ファイルなど 1 日 4.3 回(初めての送り先・鍵を読んだ後の初めての送り先・初めて触る秘密やパッケージ・初めて使う消す / 設定を変えるコマンド)。どれも、確認で通すとその場で普段に加わり、次からは聞きません。

Codex の会話記録 15 本(9 日、手 2,579 回)を同じように流すと、確認は 12 回(使った日 1 日あたり 1.3 回。初めて使う `rm`・`git push`・`kill` など)でした。

## 入れ方

```bash
python3 -m venv ~/.rs-guard/venv
~/.rs-guard/venv/bin/pip install "git+https://github.com/matu79go/reflex-sentinel@v1.1.7#subdirectory=guard"
~/.rs-guard/venv/bin/rs-guard learn          # 手元の会話記録(Claude Code・Codex)から普段を作る
~/.rs-guard/venv/bin/rs-guard install all    # 入っている道具すべてにフックを足す(1 つだけなら install codex など)
```

### 更新のしかた

```bash
~/.rs-guard/venv/bin/rs-guard update          # GitHub の最新の版を見て、新しければ入れ直す(普段の記録はそのまま)
~/.rs-guard/venv/bin/rs-guard update --check  # 新しい版があるか見るだけ
```

外へ問い合わせるのは、このコマンドを打った時だけです(フックが動く時は問い合わせません)。

### Codex での使い方

1. 入れる: `~/.rs-guard/venv/bin/rs-guard install codex`(`~/.codex/hooks.json` にフックが 3 つ入ります)。
2. Codex を開き、`/hooks` で rs-guard のフック 3 つを**信頼**する(信頼するまで動きません)。
3. あとはいつもどおり使います。普段に無い手は、Codex の画面にツールのエラーとして止まり、理由と「利用者に確かめて」が出ます。Codex があなたに確かめに来ます。
4. 普通の仕事なら「いいよ」と返事します。Codex が同じ手をもう一度実行すると通り、普段に加わって次からは止まりません。怪しければ、そのまま断ってください(あなたの返事が無いまま Codex がやり直しても通りません)。
5. 何が止まり、何を通したか: `~/.rs-guard/venv/bin/rs-guard explain`(`[codex] … → 確かめて通した` のように出ます)。

止まった時の画面の例:

```
RS: first time using the send / delete / config command shred. (Ask the user. If they approve, run the same action again and it will go through.)
```

- **確認の画面が無い道具**(Codex・Gemini CLI・Cline・Windsurf)では、普段に無い手を一度止め、エージェントに「利用者に確かめて」と伝えます。あなたが返事をした後に同じ手が来たら通し、普段に加えます。あなたの発言をはさまないやり直しは通しません。
- Codex は、入れた後に Codex の中で `/hooks` から rs-guard のフックを信頼するまで動きません。Gemini CLI は `/hooks enable-all` が要ることがあります。Cline は設定の Features でフックを有効にします。
- Cursor は、ファイルの書き込みに実行前のフックが無いため、書いた後に普段へ入れるだけです(シェル・MCP・読み込みは実行前に見ます)。
- 普段は、Claude Code と Codex は会話記録から入れた日に作ります。他の道具は、使うたびに実行された手を普段に加えていきます(普段はすべての道具で共通)。
- Windows で動く道具(Windows 版の VS Code・Antigravity・Cursor など)には、Windows の Python で同じ手順で入れてください(WSL に入れた物は Windows の道具からは呼ばれません)。コマンドは `%USERPROFILE%\.rs-guard\venv\Scripts\rs-guard.exe` です。WSL の中の Claude Code・Codex の会話記録から普段を作る時は `learn --projects \\wsl.localhost\<ディストリ>\home\<ユーザー>\.claude\projects` のように渡します。
- Antigravity には発言のフックが無いので、依頼の文は使いません(手の判定は動きます)。
- `install` は既存のフックを残し、初めて触る設定は元を `<設定>.rs-guard.bak` に保存します。外す時はこれに戻すか、rs-guard の行を消します。
- 確認の回数と理由: `rs-guard status` / `rs-guard explain`。
- 理由の文は `LANG` に合わせて日本語か英語です(`~/.rs-guard/config.json` の `"lang": "ja"` か `RS_GUARD_LANG` で固定)。
- 依存するパッケージはありません(Python 3.9 以上)。

## 判定の流れ

すべての手(シェル・ファイル・スクリプト・MCP・Web)を、次の 2 つで見ます。どちらかに当たれば確認を求めます。

### すべての手

手を区分に分けます: 送る(通信・公開・送信)/ 消す(rm・kill・git reset など)/ 設定を変える(鍵・crontab・chmod・sudo・設定ファイル)/ 実行する(スクリプト)/ 手元の作業。シェルの文はコマンドごとに分けます(引用符の中は切らない、ヒアドキュメントの中身は捨てる、`ssh 相手 '…'` と `bash -c '…'` の中も見る)。走らせるスクリプト(`python x.py`・`python -c "…"`)は中身も読み、通信のライブラリと送り先を見ます。

| 合図 | 確認を求める時 |
|---|---|
| R3 | 鍵・設定を読んだ後に、初めての送り先へ送る |
| R7 | 貼り付けた文(Claude Code の `<pasted_content>`)にある指示に、そのまま従う |
| R1x | 送る・消す・設定の手で、Web・接続先の結果から来た値を普段に無い形で使う |
| R8 | 初めて触る秘密(鍵の環境変数・`.env`・鍵のファイル)・居座り先(`.bashrc`・git の hook・cron・`/etc/`)・入れるパッケージ |
| R5 | 初めての送り先(ssh の相手・scp / rsync の host・送る curl の URL・git push の相手・MCP の接続先・メールの宛先・スクリプトの中の URL) |
| R6 | curl・wget で、読んだ中身(検索以外)に書かれていた先を普段に無い形で取りに行く |
| R2r | 送る・消す・設定を変えるコマンドを初めて使う |

あなたの言葉に出ている送り先・秘密・パッケージは通します(貼り付けた文に出ている物は通しません)。

### MCP・Web の手(似た過去の依頼と比べる)

1. 外に作用するツールだけを見ます: MCP のツールで名前が send / create / update / delete / invite / share / post / copy / batch … で始まる物と、Web を開く手(WebFetch)・Web の検索(WebSearch。検索の言葉の中のメール・URL・長い英数字だけを見る)。設定 `~/.rs-guard/config.json` の `extra_tools` で足せます。
2. 引数の値(メール・URL・ID・短い文字列)ごとに出どころを決めます: 依頼に出ている / どのツールの結果に出ている / どこにも無い。
3. 値がすべて依頼から来ているなら通します(あなたの指示そのもの)。
4. 同じ会話で同じ形(ツール・引数名・出どころ)が既に通っていれば通します。
5. 過去の依頼で一番近い物(単語の重なり)を探し、そこで同じツールを、同じ出どころの値で使っていれば通します。それ以外は確認を求めます。
6. Web を開く手は URL だけを見ます。依頼・検索の結果・モデル自身が書いた URL は通します。行き先が検索以外のツールの結果(読んだページ・メール・ファイル)に書かれていた時だけ、普段と比べます。

「今の依頼」は、最後の 3 回のあなたの発言です(「いいよ、すすめて」のような続きだけでは、仕事の種類が分からないため)。

すぐ止めたい合図は `~/.rs-guard/config.json` の `"deny_rules": ["R3", "R7"]` のように書くと、確認ではなく拒否になります。

## 置き場とプライバシー

| ファイル | 中身 |
|---|---|
| `~/.rs-guard/normal.jsonl` | 普段(MCP・Web): 依頼の文、使った手の名前、引数名、出どころの区分。**値そのもの(宛先・本文)は残さない** |
| `~/.rs-guard/seen.jsonl` | 普段(すべての手): 使ったコマンドの名前、出どころの区分、送り先・秘密・パッケージの**ハッシュ**(この機械だけの乱数 `salt` を混ぜる。名前そのものは残さない) |
| `~/.rs-guard/decisions.jsonl` | 判定の記録(何を、なぜ確認したか) |
| `~/.rs-guard/done.jsonl` | 確認のあと実行された手の番号だけ(通したか拒否したかを `explain` で出すため) |
| `~/.rs-guard/sessions/` | 会話ごとの覚え書き(あなたの発言とツールの結果)。Claude Code の会話記録は遅れて書かれることがあるため、直前の結果を見落とさないように残す。7 日で消す |

すべて権限 600 で、外へは何も送りません。

## 範囲と弱い所

- 普段の範囲内での悪用は止められません(いつも送る相手に違う中身を送る、前にも見たことのある秘密をまた見る、など)。
- 読んだファイルの中の指示は、それに従った**手**(初めての送り先・秘密・居座り先・パッケージ)で止めます。指示そのものは見ません(コーディングでは、README や設計書の手順どおりに動かすのが普通のため)。害の無いコマンド(`echo` など)を走らせるだけの注入は止めません。
- スクリプトの中の通信は、実行の時にディスクにあるファイルと `-c` の文から読みます。送り先を実行中に組み立てる・別のファイルから読む・バイナリの中で送る、といった物は見えません。実際に出ていく通信を見る層(手元のプロキシ・firewall)と並べてください。
- コマンドの見分けは決まった規則(名前の一覧と正規表現)です。一覧に無い道具で送る手は「初めてのコマンド」としては拾いません。
- 初めての種類の依頼では、外に作用する手のたびに確認を求めます(使うほど減ります)。
- 会話記録は末尾 4 MB だけ読みます(速さのため)。それより前の結果に出た値は「どこにも無い」扱いになり、Web を開く手では通ります。
- Claude Code 以外の道具は、各道具の公式の資料(2026-10 時点)の入力の形で試験しています。道具の版で形が変わると読めないことがあります(その時は何もせず通します)。

## 先行研究との関係

正常な実行の記録から「許す手の流れと値の出どころ」を学ぶ考えは、[Agent-Sentry](https://arxiv.org/abs/2603.22868)(ASR 3.7 %)と [Praetor](https://arxiv.org/abs/2604.26274)(LLM なし、人の承認を取り込む)とほぼ同じです。値に出どころの印を付ける考えは [CaMeL](https://arxiv.org/abs/2503.18813) にあります。RS guard が足したのは次の点です。

- 研究用の記録ではなく、**利用者の手元に既にある会話記録**から、入れた日にその人の普段を作る。
- 実際の会話の形への合わせ込み(続きの発言、同じ会話での繰り返し、遅れて書かれる会話記録)。
- 道具のフックにそのまま入る形(`pip install` と 2 つのコマンド)。

## 再現

`repro/` に AgentDojo と CodeIPI での評価のコードがあります(AgentDojo の `runs/`・CodeIPI の問題は MIT。同梱していません)。

```bash
python repro/dojo_gt.py --src <agentdojo>/src/agentdojo/default_suites --out gt.json
python repro/dojo_product.py --runs <agentdojo>/runs --gt gt.json --seen-task --model gpt-4o-2024-05-13
# CodeIPI: 注入に「もし従っていたら」止まるか(普段 = 手元の Claude Code の会話記録)
python repro/codeipi_counterfactual.py --bench <CodeIPI の samples.json>
```

単体試験: `python -m pytest -q tests`(試験だけ pytest が要ります)。
